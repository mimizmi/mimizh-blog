
脚本编程的意义在于分离游戏开发逻辑和游戏引擎。

在原则上游戏逻辑部分代码隶属于游戏引擎项目，然而这两者的实际开发中的灵活性和复杂度是不等价的。对于游戏引擎的变更和开发通常是缓慢而稳定的，而游戏部分的开发却是迅捷而多变的。

为了提供更便捷的游戏开发流程，将这两者分离是非常有必要的。

想象Java语言为了解决跨平台的难题所使用的虚拟机模式，Java通过编译器转译成次级语言后由汇编器转译为Java虚拟机所需的字节码，运行时通过JVM进行调度执行。

游戏脚本之于游戏引擎，就使用这样一个虚拟机的中间概念，虚拟机通过游戏引擎所提供的结构实现以进行交互，而游戏脚本将由虚拟机调度执行，由此游戏开发者不再需要关心庞大而“冗余”的游戏引擎项目工程，游戏脚本使用的语言也完全可以区别于游戏引擎所使用的语言，且具有天然的跨平台性。(因此可以理解在游戏引擎成为热门概念以前的游戏，大都愿意使用Java进行开发，换句话说，游戏引擎学科是吸收囊括了软件开发各个领域的精华的复杂集合体。

### 结构化的脚本编程语言

游戏脚本到底还是脚本，脚本系统的理念很朴素，为了方便人的使用，我们制定高级语言，但实际运行时，需要考虑到机器的便捷性，转译成符合CPU低级语言是很有必要的，只是在游戏引擎中的脚本，我们的目标是符合虚拟机的字节码，而不是CPU。

这个过程的设计包括：
* 高级语言语法设计
* 制作编译高级语言的编译器
* 制作汇编器汇编低级语言(生成字节码)
* 将虚拟机静态库链接到游戏引擎

##### 语法分析

在提取到结构化干净的源代码后，首先要判断语法正确性，这一步的结果表示通常是抽象语法树(Abstract Syntax Tree)

##### 语义分析

有时语法正确的句子语义并不一定合法，因为语法是抽象的，语义是具体的。譬如说`int Q = "Hello" + 3.14` 语法上来说就是两个数进行相加的操作，但显然我们知道一个字符串与一个浮点型进行相加操作语义上是无意义的，也就是非法的。

#### 总结

以书中XtremeScript系统为例

##### 高级部分
* 基于XtremeScript语言。XtremeScript语言是一种C-subset语言，该系统中的所有脚本都是用它编写。该语言应该设计的尽量和C/C++语言相似，这样就会使得程序设计人员更加熟悉这个环境。
* 使用XtremeScript编译器来对高级代码进行编译以生成一个ASCII格式的汇编源文件。随后对该文件执行汇编操作
* 系统中含有一个预处理程序，该程序可以对许多常见的指令进行替换操作。
* 高级代码将会为潜在的脚本系统提供一个用户接口

低级部分
* 基于一种符合Intel 80X86 语法的简单的汇编语言。为了使事情变得一致和统一，我们再一次有意使用比较相似的语法。
* 使用XtremeScript汇编程序将汇编语言汇编成为二进制的可执行脚本，这些脚本文件由字节码组成
* 此外，我们还提到了其他实体，如反汇编程序和一个简单的调试器。前者负责将可执行的脚本反过来转化为ASCII格式的汇编语言源文件，后者为编译脚本提供了一个可控制的交互性执行环境。

运行时间
* 在运行时间里，脚本在XtremeScript虚拟机(XVM)内部被执行
* XtremeScript虚拟机是一个可以嵌入的组成部分，它封装在一个静态链接库内，并且可以很容易地链接到游戏工程中
* XtremeScript虚拟机通过使用API函数在运行脚本和游戏引擎之间提供了一个接口。
* 多个脚本可以同时载入并运行
* 通过使用消息系统，游戏脚本间可以相互通信
* 系统为每个正在运行的脚本提供了一个保护环境，这个环节包括它自己的内存块、代码、堆栈空间，以及消息队列。游戏脚本不能超出这片地址空间，这样确保了高层的稳定性
* 系统中还添加其他一些安全措施，例如循环超时设定。
